# Работа с архивом, дневником и памятью в Codex/Claude

## Что входит в приложение

Навык `meeting-archive-files` — самостоятельный необязательный помощник для пользователя, который хочет анализировать совещания и сохранённые чаты через AI. Он работает с выбранными файлами и не зависит от корпоративной платформы, архитектуры или памяти другого проекта. Приложение не запускает его автоматически. Исходники навыка находятся в `skills/meeting-archive-files` в этом репозитории; установка навыка и его обновление не требуют пересборки приложения.

Порядок анализа, схемы файлов и журнала — в [SKILL.md](../skills/meeting-archive-files/SKILL.md). Укажите ассистенту выбранную папку или передайте файлы. При вызове навыка для анализа заметки и записная книжка ведутся по умолчанию. Указание «только ответ» или «без сохранения» оставляет файлы неизменными.

Для переписки см. [руководство архива чатов](CHAT_ARCHIVE.md) и [справку skill](../skills/meeting-archive-files/references/chats.md). В «Архиве чатов» сначала отметьте нужные беседы и сохраните выбранные: обнаруженный чат без выгруженных сообщений не является готовым источником анализа. Автоматика по умолчанию выключена, а после включения сохраняет новые сообщения; старую историю ранее обнаруженных чатов нужно запросить вручную. Включённые типы вложений скачиваются и при ручном сохранении истории; несохранённые или ограниченные по размеру файлы нельзя считать прочитанными. Режим совещаний и его версия fingerprint сохраняются.

## Подключить навык локально

Для Codex пользовательская папка навыков — `.agents/skills` в домашней папке, для Claude Code — `.claude/skills`. Можно использовать и одноимённые папки открытого проекта. Основание: [Codex](https://learn.chatgpt.com/docs/build-skills), [Claude Code](https://code.claude.com/docs/en/skills).

Откройте Windows PowerShell **в корне скачанного репозитория meeting-archive**, без прав администратора. Скопируйте навык для двух локальных ассистентов:

```powershell
$taskSkillSource = Join-Path (Get-Location) 'skills\meeting-archive-files'
if (-not (Test-Path -LiteralPath (Join-Path $taskSkillSource 'SKILL.md'))) {
    throw 'Откройте PowerShell в корне репозитория meeting-archive'
}
$taskSkillParents = @(
    (Join-Path $env:USERPROFILE '.agents\skills'),
    (Join-Path $env:USERPROFILE '.claude\skills')
)
foreach ($taskSkillParent in $taskSkillParents) {
    New-Item -ItemType Directory -Path $taskSkillParent -Force | Out-Null
    Copy-Item -LiteralPath $taskSkillSource -Destination $taskSkillParent -Recurse -Force
}
```

Это копирует только навык, не записи совещаний. Повторное выполнение обновляет этот навык; свои изменения заранее сохраните отдельно. Откройте архив и новую сессию. В Codex вызовите `$meeting-archive-files`, в Claude Code — `/meeting-archive-files`. Если он не появился, перезапустите ассистента и проверьте `SKILL.md` в соответствующей папке. Дайте доступ именно к выбранному архиву и заметкам, не к секретам приложения.

## Облачный Claude, Cowork и обычный чат

Локальная папка Claude Code не устанавливает навык в аккаунт Claude/Cowork. Для продуктов с пользовательскими навыками можно загрузить отдельный ZIP через настройки аккаунта; доступность зависит от продукта. См. [официальную инструкцию Claude](https://support.claude.com/en/articles/12512198-how-to-create-custom-skills).

Если установка недоступна, передайте `SKILL.md` как инструкцию вместе с выбранными материалами. Облачный чат не читает диск автоматически. Передавайте только разрешённое содержание; служебный профиль `%LOCALAPPDATA%/MeetingArchive`, токены и секреты не передавайте. Если чат не может записать в архив, он должен вернуть готовые файлы заметок/журнала и сообщить, что локальный дневник не обновлён.

## Какие файлы читать

По умолчанию ассистент читает **bitrix/transcript.md** и **local/<полный запуск>/transcript.md**. TXT, JSON, SRT и VTT — форматы тех же результатов; одновременно читать их все не нужно. JSON используют для структуры и точных сегментов, SRT/VTT — для субтитров. Если MD отсутствует, допускается TXT, затем JSON с указанием замены.

В bitrix лежит текущий текст в трёх форматах. **versions хранит только действительно прежние изменённые тексты**, а не второй экземпляр текущего. Первая загрузка не создаёт историю; неизменившийся текст не переписывается. Старые полные побайтовые дубликаты текущего текста удаляются при следующей загрузке этой встречи; прежние редакции и посторонние файлы сохраняются.

**run.json** — служебная карточка локального запуска, не токен: модель, устройство, диаризация, длительность, режим и sample. Короткий тест с sample=true не считается полным разговором. В новых результатах run.json.source_files и transcript.json.metadata.source_files содержат относительные пути записей от встречи. Для старых результатов состав ищут в metadata.source_files и именах segments[].source_file; старый абсолютный путь не разрешает чтение другой папки.

meeting.json содержит подсказки **reading**: предпочтительный формат Markdown, текущий Follow-up, последний полный локальный MD и путь записной книжки. Подсказка последнего запуска не заменяет проверку охвата: разные запуски могут содержать разные дорожки. Эти пути относительны встрече и сохраняют смысл при переносе целого архива. Старый manifest без reading поддерживается навыком. Перенос пользовательских файлов и перенос служебного профиля приложения — разные операции; указатели для AI не выполняют миграцию настроек/SQLite.

## Где сохраняются заметки

Подробный разбор хранится **в notes конкретной встречи**. Общая записная книжка находится **в корне архива, в _notebook/<портал>**, и объединяет встречи этого портала. Она содержит короткие итоги и ссылки, а не копии полных расшифровок или разборов.

В обычной распакованной Windows-поставке корень архива — Данные/Совещания рядом с EXE; книжка располагается в Данные/Совещания/_notebook/<портал>. При выборе другого корня она остаётся рядом с материалами там. Хранение в данных позволяет сохранить книжку при замене программы и переносить её вместе с архивом. Разные порталы ведутся отдельно.

| Файл | Назначение |
|---|---|
| notes/analysis-YYYYMMDD-HHMMSS-<fingerprint8>.md внутри встречи | Подробный разбор и источники |
| notes/ai-analysis.json | Статусы, хеши источников и ссылка на готовый разбор |
| _notebook/<портал>/STATE.md | Короткий указатель текущего состояния и ссылок |
| _notebook/<портал>/MEETINGS.md | Хронология: одна запись на встречу, 2–5 строк итога и ссылка на разбор |
| _notebook/<портал>/DECISIONS.md | Решения и история их изменения |
| _notebook/<портал>/TASKS.md | Поручения, источники, названные владельцы/сроки, известный статус исполнения |
| _notebook/<портал>/QUESTIONS.md | Открытые вопросы и противоречия |
| _notebook/<портал>/journal/YYYY-MM-DD.md | Этапы анализа и их проверка |
| _notebook/<портал>/memory/<тема>.md | Долговременный контекст по необходимости |

Файлы создаёт ассистент при анализе; приложение само не запускает AI и не заполняет дневник. По умолчанию навык сохраняет разбор и обновляет книжку, если есть права записи. Пользовательский дневник имеет приоритет. Существующий _assistant не переносится и не дублируется автоматически. Пустые реестры не обязательны.

Markdown-ссылки рассчитываются относительно файла, в котором они стоят. При переносе всего архива они продолжают работать; перенос одной заметки отдельно от источников может их нарушить. Место новой установки или буква диска не должны попадать в ссылки.

## Как избегать повторов

Ассистент сравнивает цель и хеши реально выбранных MD/run/существенных метаданных с notes/ai-analysis.json. Изменение updatedAt, статусов загрузки или подсказок reading само по себе не запускает повторный разбор. При совпадении и сохранённом готовом результате используется этот результат. Если потерялась только запись в общей книжке, её восстанавливают из разбора без повторного чтения речи. Новая транскрипция, охват или цель создают новую редакцию заметки с причиной; историю не стирают. При переходе инструкции с версии 1 на 2 может потребоваться одно обновление, последующие неизменённые прогоны пропускаются.

Follow-up и локальный текст сопоставляются по охвату/таймкодам, а не склеиваются подряд. Расхождения отмечаются. SPEAKER_00 не доказывает имя; поручение из разговора не означает выполнение. Без проверки аудио ассистент не должен заявлять, что речь проверена.

## Примеры запросов

Codex:

> Используй $meeting-archive-files. В открытом архиве разбери новые полные встречи за последнюю неделю. Читай Markdown, выдели решения, поручения и вопросы, обнови записную книжку портала. Неизменённые готовые разборы используй повторно.

Claude Code:

> /meeting-archive-files Разбери выбранную встречу, сопоставь Follow-up и локальный MD, сохрани разбор и обнови общую книжку её портала.

Продолжение:

> Используй meeting-archive-files. Прочитай STATE записной книжки портала, покажи открытые поручения и вопросы со ссылками. Новые встречи не анализируй.

Только чтение:

> Используй meeting-archive-files. Ответь на вопрос по выбранной встрече без сохранения заметок и изменения дневника.

## Проверить результат

Ассистент должен дать ссылки на реально созданные разбор и STATE, назвать обработанные/пропущенные встречи и ограничения. При повторе одной задачи с неизменными источниками новый разбор/вторая запись MEETINGS не создаются. При изменении текста сохраняется новая редакция, в книжке обновляется ссылка на актуальный разбор, история решений сохраняется.

## Основание структуры

Используется простой принцип локальных Markdown-файлов и связанных дневниковых записей, описанный в [Obsidian](https://obsidian.md/help/data-storage) и [Daily notes](https://obsidian.md/help/Plugins/Daily%2Bnotes). [Joplin](https://joplinapp.org/help/apps/note_history/) отдельно хранит прежние редакции. Это источники выбранного подхода, не зависимости приложения: устанавливать их не требуется.
