# Подключение Bitrix24

## Короткие звонки без текста Follow-up

Завершённый звонок длительностью меньше минуты без готового текста получает статус «Короткий звонок». Это вывод по длительности и наличию материалов, а не полученное из API сообщение об отказе BitrixGPT. Follow-up обрабатывает звонки от одной минуты: https://helpdesk.bitrix24.ru/open/23529044/.

Архив прекращает ожидание текста такого звонка. Если аудио запрошено, но ещё не появилось, очередь продолжает ждать запись. Скачать аудио и добавить файл с компьютера можно в блоке «Исходная запись». Локальная расшифровка использует общий блок обработки; дополнительных кнопок для коротких звонков нет. Автоматическая обработка подчиняется существующим настройкам, готовности модели, расписанию и паузе.

«Проверить материалы Bitrix24» и обновление каталога позволяют получить текст, если он появился позднее. Сохранённый текст имеет приоритет перед ограничением длительности. При неизвестной длительности или звонке от минуты ожидание работает как прежде.

Meeting Archive сохраняет данные на компьютере. В сборке нет общего client secret, подключённого портала или адреса компании. Реквизиты вводит владелец своего приложения; секреты сохраняются через Windows DPAPI. Новое подключение проверяет user.current и call.followup.list до замены действующего.

## Вход на этом компьютере через localhost

Это выбранный по умолчанию способ для нового профиля: вкладка OAuth → «На этом компьютере · localhost · по умолчанию». Адрес возврата — `http://localhost:8765/callback`. Необязательные HTTPS/OOB/webhook выбираются вручную; сохранённое рабочее подключение не переключается автоматически.

С версии 0.2.2 Meeting Archive принимает ответ авторизации непосредственно на `http://localhost:8765/callback`. Используется уже запущенный локальный сервер приложения. Дополнительная программа, сертификат, открытие порта в роутере и публикация маршрута не требуются для этого способа входа. Браузер должен работать на том же компьютере, что и Meeting Archive.

1. Запустите `MeetingArchive.exe` и откройте интерфейс из трея. Если порт 8765 занят, приложение сообщит об этом; завершите другую программу, занимающую этот порт, и повторите запуск. В том числе проверьте, не запущено ли ожидание входа в другом локальном приложении.
2. На своём портале откройте Разработчикам → Другое → Локальное приложение. Нужны права на создание приложений. Выберите серверный вариант и включите «Использует только API», если такой переключатель доступен.
3. В поле адреса обработчика / Redirect URI укажите точно `http://localhost:8765/callback`. Сохраните и установите приложение согласно форме вашего портала. В документации Bitrix24 адрес возврата берётся из карточки приложения: параметр в ссылке авторизации не заменяет эту настройку.
4. Выдайте права `call`, `user_basic`, `disk` и `im`. Они нужны для материалов совещаний, определения текущего пользователя и файлов записи. Наличие прав не отменяет ограничения тарифа и доступности конкретного метода.
5. В Meeting Archive откройте «Подключение Bitrix24» → OAuth → «На этом компьютере · localhost». Введите адрес своего портала, Client ID и Client secret из карточки приложения. HTTPS-обработчик в этом режиме не заполняется.
6. Нажмите «Открыть вход Bitrix24» и войдите в браузере. Программа должна оставаться запущенной. Bitrix24 возвращает одноразовый код на localhost; приложение сразу обменивает его на токены через HTTPS. Код и секрет не нужно копировать в чат или в файлы исходников.
7. Проверьте, что интерфейс показывает подключённый портал и ваш профиль. Перед сохранением новых реквизитов приложение запрашивает `user.current` и `call.followup.list`. При ошибке прежнее подключение сохраняется. Успешный вход подтверждает доступ, но сам по себе не означает, что у всех совещаний есть записи и тексты.

OAuth использует одноразовый случайный state, привязку к порталу и member_id и сохранение секретов через Windows DPAPI. После входа приложение проверяет текущего пользователя и доступ к каталогу через REST API. Поле scope в ответе сервера токенов может содержать служебное app; фактические права проверяются на подключённом портале.

При сообщении «доступ к материалам запрещён» проверьте пользователя подключения и выполните новый вход после сохранения прав приложения. При недействительном/отозванном webhook замените его либо выберите OAuth. Отказ REST API не означает пустой каталог. Реальный `ACCESSDENIED` нельзя исправить одной сменой текста сообщения: новый вход должен пройти проверку API.

**Если форма не принимает HTTP localhost.** По официальной документации серверного локального приложения HTTPS требуется для адреса обработчика при регистрации. Фактическое принятие localhost зависит от формы и настроек портала; настольный клиент Bitrix24 не отменяет эти требования. Если сохранить приложение с этим адресом нельзя, используйте следующий вариант — собственный HTTPS-обработчик. Программа не создаёт самоподписанный сертификат и не отключает проверку TLS. «Локальное приложение» Bitrix24 означает приложение одного портала; установленные программы могут при этом работать на компьютере.

## Свой HTTPS-обработчик для локального приложения

1. Владелец размещает необязательный сервис из oauth_relay на собственной площадке с HTTPS. Его адрес берётся из настроенного домена. Подробности развёртывания — oauth_relay/README.md в исходниках; менять инфраструктуру компании автоматически приложение не будет.
2. В разделе «Подключение Bitrix24» выберите «Через свой HTTPS-обработчик», укажите базовый адрес своего сервиса. Мастер покажет два полных адреса.
3. Откройте базовый адрес с суффиксом /oauth/health. Ожидается JSON: protocol=meeting-archive-oauth-relay, version=1, credentials=desktop-only, ваш портал в allowed_portals. HTML, 404 и перенаправление не подтверждают готовность. Проверка сервиса не подтверждает OAuth.
4. На своём портале: Разработчикам → Другое → Локальное приложение, серверный вариант. Первоначальная установка — адрес из поля мастера с /oauth/install; обработчик — адрес с /oauth/callback. «Приложение само завершает установку» выключено; название пункта меню пустое. Выберите права call, user_basic, disk, im. Создание требует прав администратора или разрешения на приложения.
5. Сохраните приложение. Client ID и Client secret возьмите из его карточки, введите только в Meeting Archive. Не передавайте их в чат и не добавляйте в Git.
6. Нажмите «Открыть вход Bitrix24». Авторизуйтесь в браузере на том же ПК. Возврат идёт через HTTPS-сервис на http://127.0.0.1:8765/oauth/callback; Meeting Archive должен работать, порт 8765 свободен.
7. Успех: подключение подтверждено, реальный каталог загружен. Отдельно проверить обновление токенов после истечения access token. Ошибка нового входа сохраняет прежнее подключение.

Сервис не хранит секрет приложения или рабочие токены desktop. Установочный POST Bitrix24 может содержать токены установщика: сервис отбрасывает тело. Оператор запрещает журналирование query, тела и Location на HTTPS-прокси. Авторизация и refresh идут напрямую с ПК на oauth.bitrix.info.

## Массовое приложение с кодом авторизации

Вариант «Код авторизации» требует зарегистрированного и установленного массового приложения с поддержкой OOB. Обычный Client ID локального приложения не подходит. Реквизиты получать в партнёрском кабинете Bitrix24; после входа код переносится в Meeting Archive. Код краткоживущий и не сохраняется. Программа не имеет встроенного общего клиентского секрета. Регистрация в партнёрском кабинете, установка и публикация в Маркет — отдельные этапы.

## Входящий webhook

На своём портале: Разработчикам → Другое → Входящий webhook. Создайте под пользователем, чья история нужна; права call, user_basic, disk, im. В Meeting Archive вставьте полный базовый URL без имени REST-метода и нажмите «Проверить и подключить». Успех означает ответы реального профиля и каталога. 403, отсутствие метода или тарифа не являются пустым каталогом. Webhook — секрет; отзыв выполняется на портале.

## Какие материалы можно скачать

Каталог строится по call.followup.list с личным фильтром и не является всей историей звонков портала. outcomes показывает готовые AI-блоки, включая transcription. tracks показывает предоставленные записи. Программа сохраняет признаки доступности без секретных ссылок и без скачивания аудио/полного текста на первом проходе. Колонки показывают «Можно скачать», «Ожидается» либо отсутствие предоставленной записи. Пустой tracks не доказывает, что локальной записи на компьютере нет. Импортируйте её отдельно. Текст, который портал пока не предоставил, нельзя гарантированно восстановить.

Общий счётчик — число совещаний сохранённого каталога, а прогресс синхронизации — число записей текущего прохода. Эти числа не являются количеством встреч с включённым Follow-up и без него.

Источники проверены 03.10.2026: [локальные приложения](https://apidocs.bitrix24.com/local-integrations/local-apps.html), [OAuth](https://apidocs.bitrix24.com/settings/oauth/index.html), [установка](https://apidocs.bitrix24.com/settings/app-installation/local-apps/installation-callback.html), [поля Follow-up](https://apidocs.bitrix24.com/api-reference/telephony/follow-up/fields.html), [запись звонка](https://helpdesk.bitrix24.ru/open/22079566/).

## Название чата и продление подключения (0.2.10)

Каталог получает chatId до загрузки материалов. Название читается отдельно через im.dialog.get и кэшируется на сутки; для него нужно право «Чат и уведомления (im)». Без im каталог продолжает работать с ID чата и сообщает о недостающем праве. Добавьте im в карточке локального приложения, сохраните её и выполните новый вход в Meeting Archive. Фильтр «Чат» ищет по названию или точному ID и действует совместно с темой и участниками. Первое обновление старого каталога повторно получает метаданные, не скачивая записи и тексты.

OAuth обновляется за минуту до сохранённого срока окончания. Если call.followup временно возвращает ACCESSDENIED, приложение один раз обновляет пару токенов и повторяет запрос. Постоянный отказ не скрывается: реальные права пользователя и доступ к конкретному чату по-прежнему обязательны. Фоновая проверка повторяется с задержкой после ошибки.

Источники: [поля Follow-up](https://apidocs.bitrix24.com/api-reference/telephony/follow-up/fields.html), [im.dialog.get](https://apidocs.bitrix24.com/api-reference/chats/im-dialog-get.html), [обновление OAuth](https://apidocs.bitrix24.com/settings/oauth/auto-renewal.html).

В 0.2.11 названия запрашиваются пакетами до 50 уникальных чатов, включая прогрев уже сохранённого каталога. Сохранённый кэш используется сразу; первый ответ портала всё равно требуется. Фильтр — собственный список с поиском, повторным снятием отметки и выбором нескольких чатов. Несколько чатов объединяются по «любой из выбранных», участники по-прежнему означают «все выбранные». [Официальное описание batch](https://apidocs.bitrix24.com/settings/how-to-call-rest-api/batch.html). Обычный OAuth теперь проходит в той же вкладке с возвратом на localhost; вход с одноразовым кодом сохраняет отдельное окно.
