# Архив чатов текущего аккаунта

«Архив чатов» в боковом меню показывает обнаруженные личные, групповые и рабочие чаты вошедшего пользователя. Счётчик рядом с разделом относится к каталогу чатов; найденный чат может ещё не содержать сохранённой переписки. Обновление каталога получает сведения о доступных беседах. Старая история уже существующих чатов сохраняется по ручному выбору.

## Сохранить выбранные чаты

1. Откройте «Архив чатов» и обновите каталог. В верхней сводке видны количество чатов, режим автоматического сохранения и состояние очереди.
2. Найдите нужные чаты фильтрами. Все фильтры видны сразу: текст, период, тип чата, участники, автор, направление сообщения, ответы/пересылки/цитаты, вложения, правки/удаления, системные записи и полнота истории.
3. Отметьте нужные чаты флажками. На странице показываются 50 чатов; выбор всей страницы отмечает только эту страницу. Выбранные чаты сохраняют отметку при переходе между страницами.
4. Нажмите «Сохранить выбранные». В очередь поступает вся доступная история отмеченных чатов. Просматриваемый период не ограничивает эту загрузку. Повторный запуск дополняет архив и сверяет полученные версии, не создавая копий тех же сообщений.
5. Откройте чат для чтения. Лента загружается порциями. Поиск по сохранённому архиву позволяет перейти к сообщению и его контексту. «Экспорт» создаёт ZIP выбранного чата либо сохранённого аккаунта при поиске по всему архиву.

Фильтры меняют только просмотр и состав показанного каталога. Область автоматического сохранения задаётся в настройках. Выбор чатов для ручной загрузки также не включает автоматику.

## Автоматизация в общих настройках

В существующих «Настройках» выберите категорию «Автоматизация». Здесь находятся автоматическое сохранение совещаний и чатов, виды файлов и расписания. Категории «Обновления приложения», «Системные уведомления», «Хранилище», «Входящие записи» и «Профиль расшифровки» открывают остальные параметры. Общая кнопка «Сохранить настройки» применяет изменения во всех категориях.

Автосохранение чатов, дополнительное отслеживание правок и пять типов автозагрузки вложений первоначально выключены. Проверка новых сообщений по умолчанию выполняется раз в пять минут.

| Параметр | Действие |
|---|---|
| Сохранять сообщения автоматически | После первоначального обнаружения сохраняет новые сообщения; старую историю уже найденных чатов нужно выбрать вручную |
| Все доступные / только выбранные | Область автоматического сбора; исключённые чаты не участвуют в нём, уже сохранённые файлы остаются |
| Выбранные и исключённые чаты | Выбор с поиском и отдельными отметками; один чат не входит в оба списка одновременно |
| Проверка 1/5/15 минут | Интервал фоновой проверки; по умолчанию 5 минут, сеть и очередь добавляют время |
| Отслеживание правок и удаления | Дополнительное получение уведомлений Bitrix24; включается отдельно после прочтения пояснения |
| Изображения / документы / аудио и голосовые / видео / прочие | Автозагрузка выбранных типов, в том числе файлов, обнаруженных при ручном сохранении истории |
| Также скачивать из уже сохранённой истории | Ставит в очередь подходящие вложения, сведения о которых были сохранены ранее; не запускает загрузку текста старых чатов |
| Расписание вложений | Сразу либо выбранные дни и часы компьютера; текст сохраняется вне этого окна |
| Максимальный размер автоматической загрузки | 0 — без ограничения; превышение отмечается у файла и не мешает сохранению текста |
| Папка архива чатов | В категории «Хранилище»; по умолчанию «Чаты» рядом с «Совещания», смена пути не переносит старые данные |

Первый проход обнаружения задаёт исходный каталог. Его чаты не получают автоматическую загрузку старой переписки при включении сбора. Новые сообщения в них сохраняются с момента включения автоматизации. Чаты, впервые обнаруженные после исходного прохода при включённом сборе, получают автоматическую загрузку доступной истории. Приложение не умеет достоверно определить дату создания неизвестного ранее скрытого чата: «новый» здесь означает впервые обнаруженный после исходного каталога.

Новые сообщения обрабатываются с приоритетом перед исторической догрузкой. Прогресс хранится отдельно для каждого чата и продолжается после перезапуска. Повторная проверка сохранённых сообщений отслеживает полученные правки; она не превращает несохранённую старую историю в автоматическую выгрузку.

Списки выбора показывают фактически отмеченные чаты. Удаление чата из области автоматизации отменяет дальнейший сбор в нём, но не удаляет готовый архив. Выключение типа вложений отменяет ожидающие автоматические загрузки этого типа и сохраняет скачанные файлы.

## Правки и удаления

Каждая полученная новая редакция сохраняется вместе с ранее полученным текстом. Обычная проверка может обнаружить изменение при следующем чтении сообщения. Отдельный режим уведомлений позволяет узнавать о правках и подтверждённых удалениях быстрее. После удаления остаётся отметка и ранее сохранённый текст. Исчезновение сообщения из неполной выборки само по себе не доказывает удаления.

**24 часа — срок хранения уведомлений на стороне Bitrix24, а не срок жизни архива.** Сохранённые сообщения, версии и файлы остаются в выбранной папке. Если приложение не получало уведомления больше суток, некоторые промежуточные правки или удаления могут быть пропущены. Архив отмечает возможный разрыв и сверяет остающиеся доступными сообщения.

Очередь уведомлений принадлежит пользователю и разделяется между приложениями. Подтверждение одним приложением удаляет уведомления для остальных. Поэтому дополнительное отслеживание включается явно; при работающей другой интеграции, которая читает ту же очередь, одновременное использование может приводить к пропускам. Подтверждение в Meeting Archive отправляется после надёжного сохранения полученных изменений. [Порядок получения и подтверждения](https://apidocs.bitrix24.ru/api-reference/chat-bots/chat-bots-v2/im.v2/events/event-get.html), [срок хранения](https://apidocs.bitrix24.com/api-reference/chat-bots/chat-bots-v2/im.v2/index.html).

Согласие на уведомления относится к аккаунту. Если режим включили до подключения, согласие применяется к первому подключённому аккаунту. Для другого аккаунта требуется выключить и заново включить переключатель, сохранив настройки; состояние согласия показано рядом с ним. Изменение папки того же аккаунта не требует нового согласия.

## Вложения

Включённые типы скачиваются автоматически при появлении сведений о вложении, в том числе во время ручного сохранения полной истории выбранного чата. Настройка загрузки из уже сохранённой истории дополнительно проверяет ранее собранные сведения о файлах. В обоих случаях действуют расписание и ограничение размера.

Если файл больше установленного предела, у вложения появляется причина «Превышен лимит размера»; текст сообщения и остальные сведения сохраняются. Ручная кнопка скачивания отдельного файла доступна при выключенной автоматике и обходит выбранные типы, расписание и ограничение автоматической загрузки.

Файлы скачиваются по одному, с резервом 1 ГБ, проверкой размера и SHA-256. Временные ошибки повторяются; причины недоступности видны. Имена не перезаписывают содержимое другого ID. Незавершённая загрузка не выдаётся за готовый файл.

## Полнота и переносимые файлы

У каждого чата видны охват, время проверки и ограничения. «Доступная история сохранена» означает достижение границы ответа источника для загруженного периода. Наличие чата в каталоге и автоматическое сохранение новых сообщений не означают, что старая история уже выгружена. Удалённые до начала сбора сообщения, тарифно закрытая история и недоступные оригиналы могут отсутствовать.

Список последних диалогов не гарантирует обнаружения всех скрытых чатов и веток комментариев. Каталог дополняется уже известными идентификаторами и чатами из каталога совещаний текущего аккаунта. Необнаруженная ветка не считается сохранённой; интерфейс не объявляет весь аккаунт полностью выгруженным только по списку последних бесед. [Возможности каталога Bitrix24](https://apidocs.bitrix24.ru/api-reference/chats/im-recent-list.html).

Структурированные ответы и пересылки сохраняют ID оригиналов. Отправитель отделён от автора оригинала. Цитата без подтверждённой связи не получает выдуманного автора. Дополнительный контекст не считается полной выгрузкой исходного чата. Время наблюдения редакции не выдаётся за время правки.

Переносимые файлы: `archive.json` → папка портала → `user-ID/account.json` → `chats/chat-ID/chat.json`; внутри `messages/YYYY-MM.md`/`.jsonl`, `versions/YYYY-MM.jsonl`, `context/excerpts.jsonl`, `attachments/file-ID/hash_имя`, `notes/`. Без даты источника — `undated.*`. Общая книжка аккаунта — `_notebook`. Токены и служебные ссылки скачивания не экспортируются.

SQLite содержит индекс и очередь. Потерянный индекс восстанавливается из корректных файлов при выборе той же папки и аккаунта. Заметки и книжка не переписываются. Повреждённый JSONL остаётся на месте, а ошибка восстановления не означает пустого архива.

Для AI: [meeting-archive-files](../skills/meeting-archive-files/SKILL.md) и [режим чатов](../skills/meeting-archive-files/references/chats.md). Читайте выбранные месяцы Markdown, проверяйте связи и версии по JSONL. Прежние анализы совещаний не инвалидируются.

## Нагрузка и официальные ограничения

50 чатов на странице интерфейса — размер отображения каталога. Это не пакет из 50 одновременных запросов к Bitrix24. История читается постранично: основной поиск возвращает до 200 сообщений, резервный метод — до 50. Эти размеры уменьшают число обращений, а сама очередь сохраняет прогресс между ними. [Поиск истории](https://apidocs.bitrix24.ru/api-reference/chats/messages/im-dialog-messages-search.html), [резервная история](https://apidocs.bitrix24.ru/api-reference/chats/messages/im-dialog-messages-get.html).

В облачном Bitrix24 обычные тарифы допускают устойчиво два HTTP-запроса в секунду, «Энтерпрайз» — пять. Ограничение учитывает приложения, обращающиеся к одному порталу с одного IP. Кроме частоты действует отдельный бюджет накопленного времени выполнения каждого метода. Его фактический порог задаёт Bitrix24; указанное в документации значение 480 секунд служит примером, а не универсальным пределом. `batch` уменьшает число HTTP-запросов, но не отменяет этот бюджет.

Meeting Archive отправляет REST-запросы через общий для фоновых задач клиент не чаще одного раза в секунду. Если Bitrix24 сообщает накопленное время `operating` от 240 секунд и будущий `operating_reset_at`, приложение заранее приостанавливает этот метод до сброса. 240 секунд — собственный предупредительный предел приложения, а не заявленный предел тарифа.

При ответе об избытке запросов вызовы повторяются с увеличивающейся задержкой; при превышении времени метода учитывается момент сброса `operating_reset_at`. Ограничение других приложений или нагрузка самого портала всё равно могут замедлить сбор. Поэтому задержка отражается в очереди, а обещание полного отсутствия ограничений API было бы неверным. [Лимиты REST API и обработка ограничений](https://apidocs.bitrix24.ru/limits.html).

Нужно право `im` и доступ текущего пользователя. Разработка, документация и тесты используют только вымышленные данные. Реальный портал и его варианты ответов проверяет пользователь после обновления.
