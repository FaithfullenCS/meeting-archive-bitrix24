# Новая установка и удаление данных

Расположение программы и профиль — разные вещи. EXE можно распаковать в другую папку, но параметры, ключи, каталог и очередь текущего пользователя Windows остаются в `%LOCALAPPDATA%\MeetingArchive`. Поэтому новая копия продолжает использовать выбранную прежде папку совещаний. Смена папки существующего каталога без переноса файлов нарушила бы его связи.

Для новой установки используйте `uninstall.cmd`, который находится рядом с `MeetingArchive.exe`. Он запускает входящий в комплект `scripts/reset-profile.ps1`; Python и права администратора не нужны.

1. Завершите приложение: значок Meeting Archive в трее Windows → **Выход**. Закрытие вкладки браузера не завершает приложение.
2. Дважды нажмите `uninstall.cmd`.
3. Ответьте на вопрос:
   - **1 / Enter — только профиль:** удалить параметры, локальные ключи Bitrix24/Hugging Face, каталог, очередь и временные импорты; оставить сохранённые совещания, заметки и установленные модели.
   - **2 — все данные приложения:** дополнительно удалить папки совещаний из текущего архива и собственный модуль с моделями.
   - **3 — отмена:** ничего не удалять.
4. Просмотрите найденные пути. Для подтверждения введите `DELETE`; любой другой ответ отменяет действие.
5. После сообщения об успешном сбросе запустите приложение. Оно создаст новый профиль. Выберите папки, заново подключите Bitrix24 и сохраните профиль расшифровки.

Удаление необратимо: до полного удаления скопируйте нужный архив отдельно. Скрипт не делает резервную копию секретов. Он удаляет только локальные ключи; приложение на портале Bitrix24 и токен в учётной записи Hugging Face остаются действующими до их отзыва владельцем.

При варианте 1 сохранённые файлы остаются по прежнему пути, но старый каталог/очередь сброшены. Они не появляются автоматически в новом каталоге: открыть материалы можно через Проводник, каталог Bitrix24 загрузить заново. Сброс не переносит старый архив в новую папку.

При варианте 2 скрипт удаляет только распознанные папки совещаний с `meeting.json` приложения в текущей папке архива. Посторонние файлы рядом, оригиналы импортированных записей, внешние среды и общие кэши других программ сохраняются. Пустые родительские папки могут остаться. Другие старые архивы в неизвестных скрипту местах он не ищет. Если `settings.json` повреждён или не позволяет определить архив, полное удаление останавливается.

Внешние ссылки/Windows junction в дереве папок блокируют удаление до первого изменения. Если приложение работает, скрипт попросит завершить его и запустить сброс снова. Не обходите эти сообщения ручным удалением корня пользовательской папки.

Для разработчиков: `-ProfileHome` позволяет указать отдельный профиль; `-Mode Profile` / `-Mode All` выбирают вариант, `-Preview` показывает план без удаления. `-ConfirmReset` предназначен только для заранее подтверждённого автоматического запуска; обычный CMD всегда задаёт вопросы. Если задана переменная `MEETING_ARCHIVE_HOME`, по умолчанию используется этот профиль. Автозапуск Windows удаляется только для стандартного профиля.

С версии 0.2.10 работа приложения проверяется по блокировке именно выбранного профиля Windows, а не по номеру процесса из runtime.json. Устаревший PID, переданный Windows другой программе, не блокирует удаление. Блокировка удерживается до завершения скрипта: запуск приложения во время подтверждения и удаления запрещён. При действующем приложении выводится краткое сообщение без трассировки PowerShell.
