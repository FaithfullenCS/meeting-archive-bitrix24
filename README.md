# Meeting Archive

Локальный архив совещаний и чатов текущего аккаунта Bitrix24 для Windows 10/11 x64. Программа сохраняет доступные записи, тексты и переписку в обычные папки. Дополнительный модуль создаёт локальную расшифровку рядом с текстом Bitrix24. Файлы можно открыть в Codex или Claude без API-ключей моделей и без MCP архива.

Для запуска готовой Windows-сборки **не нужно устанавливать Python или FFmpeg**. Среда базового приложения уже входит в ZIP. Распакуйте весь архив и запускайте MeetingArchive.exe вместе с папкой _internal. Для локальной расшифровки выберите модели в настройках: приложение само подготовит необходимые библиотеки и управляемый Python в вашем профиле. Первая установка моделей требует интернета и свободного места.

Поддерживаемая базовая поставка — Windows 10/11 x64. Особенности Windows ARM и видеокарт описаны в [совместимости оборудования](docs/windows-hardware.md).

Приложение включает OAuth через localhost, пустые папки данных, фильтры участников и чатов, ручную и автоматическую загрузку Follow-up с необязательным аудио, локальную расшифровку и удаление сохранённых материалов. Follow-up представляет доступную историю обработанных совещаний текущего пользователя, а не все звонки портала.

## Запуск Windows-сборки

1. Скачайте `MeetingArchive-Windows-x64.zip` из [GitHub Releases](https://github.com/FaithfullenCS/meeting-archive-bitrix24/releases).
2. Откройте свойства скачанного ZIP. Если есть флажок **Разблокировать**, отметьте его и нажмите **Применить**. Распакуйте ZIP целиком в отдельную постоянную локальную папку. Сохраните рядом `MeetingArchive.exe` и папку `_internal`. Перенос одного EXE приведёт к отсутствию ресурсов.
3. Запустите `MeetingArchive.exe` обычным двойным щелчком, без прав администратора. Откроется собственное окно Meeting Archive на WebView2; программа останется в трее. Если бесплатный компонент Microsoft WebView2 отсутствует, приложение автоматически установит его; для первой установки нужен интернет. Адрес локального сервера: `http://localhost:8765`.
4. В Windows ZIP уже находятся пустые папки `Данные\Совещания` и `Данные\Входящие записи` рядом с EXE. Новый профиль использует их по умолчанию; ранее выбранные папки сохраняются. Папки можно выбрать заново в настройках. Входящие записи — место для готовых файлов с компьютера; приложение само разговоры не записывает.
5. Подключите Bitrix24 по [инструкции](docs/bitrix24.md). Первый вариант OAuth — через локальное приложение с возвратом на `http://localhost:8765/callback`; отдельный HTTPS-сервис для этого способа не нужен. Если форма вашего портала требует HTTPS при регистрации, предусмотрен собственный обработчик. При первом входе загружается каталог метаданных. Записи и тексты скачиваются после вашего выбора.

Крестик скрывает окно в трей и сохраняет фоновую работу. Повторное открытие восстанавливает то же окно. В трее доступны открытие интерфейса, пауза автоматизации и полный выход. Авторизация и внешние ссылки открываются в обычном браузере пользователя. Автозапуск при входе в Windows включается отдельно. Новые виды автоматизации первоначально выключены.

## Архив чатов

Откройте «Архив чатов», обновите каталог, отметьте нужные чаты и нажмите «Сохранить выбранные» для загрузки всей доступной истории. В каталоге — 50 чатов на странице, сводка и все фильтры сразу; счётчик в боковом меню показывает число обнаруженных чатов. Лента сохраняет ответы, пересылки, цитаты, прежние редакции, реакции и состояния вложений. Поиск и фильтры меняют только просмотр.

Автоматическое сохранение находится в существующих «Настройках» → «Автоматизация» и применяется общей кнопкой сохранения. Оно первоначально выключено; после включения проверяет новые сообщения раз в пять минут. «Все доступные чаты» означает новые сообщения во всех доступных чатах, включая поздно обнаруженные беседы. Это не разрешение скачать их старую историю. Сообщения до включения автоматики загружаются только по ручному выбору «Сохранить выбранные». Ранее запрошенная вручную история продолжает догружаться, а сохранённый чат получает новые сообщения и проверки правок. Все пять типов автозагрузки вложений первоначально выключены; включённые типы применяются также при ручном сохранении истории. Превышение размера отмечается у файла и не мешает сохранению текста.

При обновлении до 0.2.36 прежние автоматические задания полной истории отменяются; задания новых сообщений получают ограничение по началу автосохранения. Ручные задания и скачанные материалы остаются. Случайно поставленные автоматикой файлы из старых сообщений снимаются с загрузки; явно выбранные файлы, вложения ручной истории и отдельный запрос файлов уже сохранённой истории сохраняются в очереди. Проверки новых сообщений и сведений об участниках могут быть в очереди и для не выбранных вручную чатов — они не означают полную историческую загрузку.

Полная история в файлах сама по себе не доказывает ручной выбор. Для старого архива без сохранённого подтверждения действует безопасное правило: новые сообщения автоматически, старые — по отдельному запросу. Если такой чат действительно сохранялся вручную и нужно продолжать сверять всю его историю, снова нажмите «Сохранить выбранные» для него. Это зафиксирует выбор и сверит существующий архив без дублей сообщений.

В самом первом выпуске обновление каталога ошибочно создавало полную историю с признаком «ручная». Поэтому при обновлении такие старые задания без подтверждения выбора отменяются; одного прежнего признака недостаточно. Новые проверки из того каталога становятся автоматическими и учитывают переключатель автосохранения. Подтверждённые ручные запросы и сохранённые данные остаются.

Архив разделяется по аккаунтам и устойчивым ID чатов. JSONL и Markdown с якорями сообщений позволяют читать его без приложения. Полнота и ограничения показываются у каждого чата; список последних диалогов может не обнаружить скрытые чаты и ветки. [Настройки, старая история, структура и ограничения](docs/CHAT_ARCHIVE.md).

## Ежедневная работа

- Поиск по названию или ID обновляется во время ввода; даты, длительность, состояние материалов и участники применяются сразу. Нажатие на человека в списке добавляет его, повторное нажатие снимает выбор. Несколько выбранных людей должны присутствовать вместе. Период выбирают в календаре приложения, «Сбросить» очищает все условия. Фильтры работают по сохранённым метаданным и не скачивают записи или тексты.
- Флажки выбирают отдельные встречи; Shift + щелчок по другому флажку отмечает диапазон текущей страницы. Shift + щелчок по отмеченному флажку снимает отметки диапазона. Выберите совещания в каталоге и нажмите «Скачать тексты Follow-up» (или «Скачать выбранное», если включено аудио). Фильтры помогают найти дату, длительность, название и состояние материалов. Карточка отдельно показывает аудио, текст Bitrix24 и локальные результаты.
- «Автозагрузка» забирает материалы новых совещаний, завершившихся после включения. Старые совещания скачиваются вручную. Задержанный текст повторно проверяется и догружается. Настройка «Скачивать аудио вместе с текстом» действует на автоматическую загрузку и ручные кнопки в списке и карточке. В новом профиле она выключена: сохраняется только текст Follow-up, задача не скачивает и не ждёт аудио. Для одной встречи откройте карточку → «Исходная запись» → «Скачать аудиозапись совещания». Эта кнопка загружает только запись и не включает скачивание аудио для других встреч. При выключенной настройке ручные кнопки называются «Скачать тексты Follow-up» и «Скачать текст Follow-up»; при включённой получают текст и аудио. Выбор состава ручной загрузки сохраняется в задаче, включая повторные проверки позднего текста. Последующее изменение настройки не меняет уже поставленную ручную задачу; новый ручной запрос обновляет её выбор, сохраняя отдельно запрошенное аудио. Уже сохранённые записи не удаляются.
- «Локальная авторасшифровка» обрабатывает новые сохранённые записи выбранным движком, включая ручное скачивание из Bitrix24 и импорт с компьютера. Включение авторасшифровки включает скачивание аудио и блокирует его отключение. Чтобы отказаться от аудио вместе с текстом, сначала выключите авторасшифровку. Пауза и расписание ограничивают запуск этих автоматических задач. Повторное скачивание неизменённой записи не создаёт новую расшифровку. Для запуска вручную используйте кнопку в карточке. Сначала установите выбранную модель либо используйте найденные совместимые ресурсы.
- Отдельный файл импортируется вручную. Наблюдение за папкой записей включается независимо; приложение ждёт стабильного размера и возможности чтения. Импорт без подтверждённой связи остаётся отдельной записью, которую можно вручную привязать к совещанию.
- В сравнении текст Bitrix24 и локальный текст отображаются рядом с проигрывателем. Различия не являются автоматической оценкой качества: тексты могут относиться к разным частям разговора.
- В окне импорта и в карточке самостоятельной записи выберите связанное совещание по названию или ID в списке приложения. Можно отметить только одну встречу; повторное нажатие снимает отметку.
- **Удалить материалы:** кнопка в карточке позволяет выбрать отдельные аудио/видеофайлы, запуски локальной расшифровки, текст Bitrix24 и заметки. Кнопка в каталоге работает с отмеченными совещаниями; «Настройки → Хранилище → Очистить сохранённые материалы» — со всем архивом. Перед удалением показываются объём и состав. Совещания и их метаданные остаются в каталоге. Удаление файлов нельзя отменить; для восстановления понадобятся оригиналы или повторная загрузка. Завершите или отмените задачи выбранных совещаний перед очисткой.
- **Удалить отдельные модели:** откройте этот блок в «Настройки → Профиль расшифровки», отметьте собственные загрузки Meeting Archive и подтвердите удаление. Общие библиотеки сохраняются. Модели, найденные у других программ, здесь не удаляются. После удаления выберите доступную модель в профиле либо установите нужную снова.
- Для диаризации нужны проверенный доступ Hugging Face и библиотеки обработки. Если найден только обычный Whisper, сохраните профиль с диаризацией, нажмите «Подготовить поддержку» и дождитесь установки. [Подробная инструкция](docs/diarization.md). При подготовке сохранённые веса Whisper используются повторно.

У автозагрузки и локальной обработки собственные расписания. Можно запускать сразу или разрешить начало автоматических задач в выбранные дни и часы. Время берётся из настроек Windows; ночное окно относится к дню своего начала. Например, понедельник 22:00–06:00 заканчивается во вторник. Вне окна очередь ждёт. Ручные кнопки запускаются сразу; уже начатая обработка может завершиться после закрытия окна. Расписание не пробуждает спящий компьютер и действует, пока Meeting Archive запущен.

**В звонке один на один включите Follow-up, если нужен текст Bitrix24; отдельно включите «Запись», если хотите сохранить исходник самостоятельно.** Подробности и ограничения: [инструкция Bitrix24](docs/bitrix24.md).

## Как часто приложение обращается к Bitrix24

| Проверка | Частота и объём |
|---|---|
| После подключения | Полная постраничная загрузка доступных метаданных Follow-up, без аудио и полных текстов |
| Обычная фоновая проверка каталога | После завершения предыдущего цикла — пауза 60 секунд. Проверяется диапазон от предыдущей проверки минус семь дней до текущего времени, чтобы находить поздние материалы |
| Полная сверка истории | Когда с последней успешной полной сверки прошло больше суток; при первом запуске подключённого профиля — если прежней сверки нет |
| Ожидаемые материалы выбранного или автоматически поставленного совещания | Повтор через 60 секунд в первые 15 минут ожидания, через 5 минут до суток, затем через сутки. Возраст ожидания считается от создания задачи загрузки. Если аудио включено, оно сохраняется сразу по готовности, не дожидаясь текста |
| Сетевая ошибка или ограничение API | Повтор с задержкой 2, 4, 8, 16, 32 минуты, далее до часа. При ошибке авторизации требуется повторный вход |

«Раз в минуту» означает цикл проверки, а не обязательно один HTTP-запрос. `call.followup.list` получает страницы по 20 совещаний: если в проверяемом диапазоне 100 записей, один проход делает пять запросов каталога. Между страницами есть пауза 0,2 секунды. При одной странице и постоянно запущенном приложении это примерно 60 проверок в час / 1440 в сутки; фактическое число зависит от времени ответа, числа страниц, ошибок и времени работы программы. Проверка `call.followup.get`, скачивание файлов, первоначальная загрузка, суточная сверка и ручное обновление добавляют запросы отдельно. Проверка подключения также читает `user.current` и первую страницу каталога перед полной загрузкой истории.

Каталог обновляется и при выключенных переключателях автозагрузки/авторасшифровки, и во время паузы автоматизации. Расписание ограничивает начало фактической загрузки материалов и локальной обработки; вне окна задачи ждут в очереди. Переключатели не отключают получение метаданных. Уже выбранные для скачивания совещания продолжают догружаться; суточная сверка ставит их на повторную проверку материалов даже при выключенной автозагрузке новых совещаний. Пауза автоматизации задерживает эти автоматические задачи. Для полного прекращения запросов выйдите через трей или отключите Bitrix24. Закрытие вкладки браузера оставляет фоновую проверку работающей. Поиск, фильтры и просмотр очереди обращаются к локальному приложению, а не напрямую к Bitrix24.

Программа получает доступную историю Follow-up текущего пользователя; она не наблюдает за всеми звонками портала и не подтверждает наличие записи у звонка без Follow-up. Эти интервалы задаются приложением, а не cron-службой Windows; оно не пробуждает спящий компьютер.

**От завершения совещания до локального текста:** Bitrix24 сначала публикует встречу и готовит материалы; время этой подготовки не задаёт Meeting Archive. После появления встречи очередная проверка каталога обнаруживает её примерно через минуту плюс время запросов. При включённой автозагрузке и разрешённом расписании задача проверяет доступные материалы. Новая сохранённая аудиозапись сразу ставится на локальную обработку при включённой авторасшифровке — также после ручной загрузки или импорта, без ожидания Follow-up. Свободный обработчик опрашивает очередь каждые 0,5 секунды. Другая задача, пауза, расписание, неготовая модель, сон компьютера и ошибки сети увеличивают ожидание. Длительность самого распознавания зависит от записи, модели и компьютера.

Фильтр чатов содержит чаты из каталога совещаний, а не все чаты портала. Названия читаются пакетами и кэшируются; если название недоступно, показывается ID. Несколько выбранных чатов означают «любой из выбранных», несколько участников — «все выбранные».

## Расшифровка

Откройте **Настройки → Расшифровка на компьютере**. Отметьте нужные пакеты: любые сочетания Whisper, Parakeet v3 и GigaAM v3. Можно установить несколько моделей Whisper одновременно. Общая среда устанавливается один раз, уже сохранённые модели повторно не загружаются. Активный движок и модель для следующей обработки выбираются отдельно от списка установки. Работа идёт в отдельном процессе; интерфейс и загрузчик продолжают работу. В карточке неподготовленного профиля кнопка ведёт к настройкам; готовый профиль позволяет расшифровать запись. Несколько файлов можно обработать отдельно либо объединить по порядку; этот выбор появляется только при наличии нескольких записей.

| Движок | Модели и объём весов | Особенности |
|---|---|---|
| Whisper / faster-whisper | `tiny`, `base`, `small`, `medium`, английские варианты `.en`; `large-v1`, `large-v2`, `large-v3`, `large-v3-turbo`; примерно 0,08–3,1 ГБ на модель | Многоязычное распознавание; `.en` предназначены для английского |
| Parakeet v3 | `parakeet-tdt-0.6b-v3-q8`; примерно 0,714 ГБ | Отдельный нативный runtime CPU/CUDA; поддерживаемые языки и ограничения — в каталоге |
| GigaAM v3 | `gigaam-v3-e2e-rnnt`; примерно 0,449 ГБ | Специализируется на русской речи; таймкоды границ фрагментов, без выравнивания отдельных слов |

Перед подтверждением установка показывает оценку загрузки и свободного места с учётом выбранного списка, общих библиотек и уже имеющихся файлов. Эти оценки приблизительные; нужны также место под исходники, временную обработку и архив. Полная Windows-сборка содержит установщик управляемого Python; ручная установка Python или FFmpeg для запуска не нужна. Модели загружаются после явного выбора пакетов.

Совместимые библиотеки Whisper и сохранённые модели приложение ищет автоматически в обычных папках среды и публичном кеше Hugging Face. Готовые модели отмечаются в одном каталоге и в профиле. Найденный Python используется напрямую с обработчиком Meeting Archive, сохранённые веса читаются без копирования. Для подключения не создаются снимки или NTFS-ссылки, не требуется резерв 128 МБ. Если совместимой среды нет, установщик подготовит собственную. Дополнительные выбранные Whisper-модели могут использовать найденные библиотеки; загружаются только недостающие веса. Если найденную среду удалить или существенно изменить, расшифровка может перестать работать; тогда установите собственные ресурсы Meeting Archive. Parakeet и GigaAM имеют отдельные форматы/runtime: произвольный скачанный файл не означает готовность этой реализации.

В настройках можно проверить сохранённый профиль на первых 30 секундах записи для любого из трёх движков. Сохраняются результат и время обработки именно этого профиля; при смене параметров прежний тест не подтверждает новую конфигурацию. Проверка GPU выполняет реальную операцию PyTorch, для нативного Parakeet используется диагностика doctor; предположительная таблица Whisper убрана. По умолчанию выбран GPU; перехода на CPU при ошибке GPU нет. CPU включается осознанно и может работать значительно дольше длительности записи. Для новой установки PyTorch выбирается закреплённый комплект CUDA 12.6 или 12.8 по архитектуре NVIDIA и драйверу; Intel/AMD x64 используют CPU-комплект. AMD GPU и Windows ARM имеют отдельные [границы поддержки](docs/windows-hardware.md). Язык по умолчанию — автоматический; для GigaAM это режим русской модели, а не определение языка. Определение пауз включено, шумоподавление и диаризация выключены.

Качество относительно Bitrix24 на вашей записи считается **не проверенным** до сравнения с аудио. Для GigaAM подтверждены контракты и контролируемые тесты; реальные веса и распознавание совещания требуют отдельной проверки после выбранной установки. [Установка и ограничения GigaAM](docs/gigaam.md).

Диаризация — разделение речи по говорящим — требует принятия условий двух моделей Hugging Face. [Короткая инструкция](docs/diarization.md). Метки `SPEAKER_00` не являются именами сотрудников.

«Удалить модуль» удаляет принадлежащие Meeting Archive окружение, пакеты движков и модели. Сначала проверьте показываемый объём. Записи, тексты, заметки и ресурсы других приложений сохраняются. Возможность старого внешнего адаптера оставлена для совместимости ранее сохранённых профилей; обычный сценарий использует автоматически найденную совместимую среду либо среду Meeting Archive.

## Где хранятся данные

Архив отделён от служебной папки `%LOCALAPPDATA%\MeetingArchive`. В служебной папке находятся SQLite, настройки, очередь, защищённый файл секретов и устанавливаемый модуль. Архив организован как «портал → год → месяц → время и идентификатор»:

| Путь внутри совещания | Назначение |
|---|---|
| `meeting.json` | Метаданные, состояния, относительные файлы/SHA-256 и подсказки `reading` для текущих MD/книжки |
| `audio/` | Исходные записи без изменения формата |
| `bitrix/` | Текущий Follow-up: MD для AI, JSON для структуры, TXT для простого чтения; `versions/` — только прежние редакции |
| `local/` | Отдельные локальные запуски: JSON, Markdown, TXT, SRT, VTT |
| `notes/` | Ваши заметки; приложение их не перезаписывает |

При изменении Follow-up прежний текст сохраняется в versions, новый становится текущим. При первой загрузке второй копии нет; неизменённые тексты не переписываются. Существующие точные копии текущего текста очищаются при следующей загрузке этой встречи, без удаления старых редакций. Название совещания не является ключом папки. Повторная синхронизация пропускает неизменённые файлы. Токены, webhook и секретные параметры адресов загрузки не сохраняются в архив.

Откройте папку архива или отдельного совещания в Codex/Claude. Не добавляйте записи, полные тексты, служебную SQLite и секреты в Git. Резервное копирование обычных файлов архива сохраняет его независимо от приложения. DPAPI-секреты связаны с вашим пользователем Windows: копирование `secrets.dpapi` на другой компьютер не заменяет повторный вход.

## Новая установка и сброс профиля

Распаковка EXE в другую папку сохраняет профиль текущего пользователя Windows. Для начала с чистыми настройками завершите приложение через трей и запустите `uninstall.cmd` рядом с EXE. Откроется окно выбора компонентов: программа, профиль, собственные модели, совещания и чаты. Архивы и модели по умолчанию сохраняются. Перед удалением показаны пути и объём; после — итог и ошибки. Он не требует Python или прав администратора. [Порядок действий, границы удаления и восстановление](docs/reset-profile.md).

## Разработка и сборка

Требуется Windows x64, Python для первоначального запуска установщика и PowerShell. Релиз собирается на управляемом Python 3.12.15. Команды выполняются из корня этого репозитория, без прав администратора; старое приложение расшифровки не используется:

```powershell
py -3.12 -m venv .work\bootstrap
.work\bootstrap\Scripts\python.exe -m pip install uv==0.12.22
$env:UV_PYTHON_INSTALL_DIR = Join-Path $PWD '.work\python'
$env:UV_CACHE_DIR = Join-Path $PWD '.work\uv-cache'
.work\bootstrap\Scripts\uv.exe python install 3.12.15 --no-bin
.work\bootstrap\Scripts\uv.exe venv --python 3.12.15 --managed-python .venv
.work\bootstrap\Scripts\uv.exe pip sync --python .venv\Scripts\python.exe --require-hashes requirements-dev.lock
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -m ruff check meeting_archive oauth_relay tests scripts
.venv\Scripts\python.exe -m meeting_archive.launcher
```

Сборка базового приложения не устанавливает torch, pyannote и модели:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build-windows.ps1
```

Результат: `dist\MeetingArchive-Windows-x64.zip` и файл SHA-256. Build-скрипт добавляет закреплённый `uv.exe` из dev-среды, исходники worker и hash-lock-файлы. Отдельный Python-модуль позднее устанавливается в профиле пользователя.

`scripts\lock-workers.ps1` заново разрешает Windows CPU/CUDA-профили с PyPI и официального индекса PyTorch. После изменения зависимостей нужно пересмотреть diff lock-файлов и проверить отдельные окружения. Hash-пины фиксируют артефакты; разрешение зависимостей само по себе не доказывает GPU-совместимость.

GitHub Actions собирает Windows ZIP. Тег `v*` публикует Release после успешного workflow.

## Работа с AI

В поставку входит самостоятельный [навык meeting-archive-files](skills/meeting-archive-files/SKILL.md) для Codex/Claude. Он читает **MD по умолчанию**, сопоставляет Follow-up и подходящую полную локальную расшифровку, сохраняет подробный разбор в notes встречи и обновляет **общую книжку _notebook/<портал> в корне архива**: короткие итоги, решения, поручения, вопросы и ссылки. ## Обновления и уведомления Windows

В общих настройках можно включить автоматическую проверку и скачивание стабильных версий с GitHub. Проверка выполняется примерно раз в сутки; «Проверить сейчас» запускает её вручную. После скачивания и проверки SHA-256 появляется кнопка «Обновить и перезапустить». Установка ждёт завершения текущих задач, затем перезапускает приложение. «Отменить ожидание» возвращает обычную работу очереди. Для разработки из Python установка недоступна.

Обновление заменяет только программные файлы из манифеста сборки. Папка «Данные», выбранный архив, профиль, модели и неизвестные пользовательские файлы сохраняются. Прежние программные файлы остаются в резервной копии внутри служебной папки профиля. При неудачном запуске новой версии приложение пытается восстановить предыдущую; если новая копия не отвечает на штатное завершение, файлы работающего процесса не заменяются и ошибка сохраняется. Нужны права записи в папку приложения и свободное место для загрузки, распаковки и резервной копии. Новые зависимости расшифровки при обновлении приложения автоматически не устанавливаются.

Версии до 0.2.17 не умеют обновляться внутри приложения: на актуальную версию со встроенным обновлением требуется перейти один раз через ZIP. После этого используется встроенное обновление. Интернет нужен только для проверки и загрузки версии; GitHub-токен, сервер и платная подписка пользователю не нужны.

Системные уведомления включены по умолчанию: завершение загрузки, локальной расшифровки и ошибки, требующие внимания. Главный переключатель отключает показ целиком, сохраняя выбранные типы. Изменения действуют после сохранения настроек. Несколько завершений одного типа за десять секунд объединяются. Ожидание материалов, автоматические повторы и отмена не создают сообщения об успешном завершении или окончательной ошибке.

Нажатие на уведомление открывает совещание, очередь задач или настройки подключения. Если приложение закрыто, Windows запускает его через зарегистрированный для текущего пользователя протокол `meetingarchive:`. Регистрация обновляется при запуске Windows-сборки из новой папки. Уведомления создаются локально. Их показ зависит от настроек Windows и режима «Не беспокоить»; кнопка «Проверить уведомление» позволяет проверить доставку в Windows, но не подтверждает, что баннер был виден на экране.

## Правки и удаления: что именно сохраняется

Архив — как тетрадка, куда приложение переписывает сообщения, которые увидело.

- Вы написали «встреча в 10», и архив это сохранил. Позже вы исправили на «встреча в 11». Когда приложение получит исправление, в архиве останется новый текст и прежняя сохранённая версия.
- Если сообщение удалили в Bitrix24, уже сохранённая копия остаётся. Когда источник явно подтвердит удаление, архив поставит отметку удаления. Если приложение ни разу не видело сообщение до удаления, восстановить его текст оно не сможет.
- Обычное автосохранение проверяет новые сообщения по выбранному интервалу. Отдельные повторные проверки уже сохранённого обнаруживают полученные правки. Между проверками несколько промежуточных редакций могут остаться незамеченными.
- «Быстрее получать правки и удаления» дополнительно подключает уведомления Bitrix24: «это сообщение изменили» или «это сообщение удалили». Приложение не становится мгновенным: уведомления проверяются примерно раз в 15 секунд, но общая очередь запросов, пауза и ограничения портала могут отложить обработку.

**24 часа — срок уведомления, а не срок хранения архива.** Уведомление можно представить как записку на двери: источник держит её сутки. Сохранённые сообщения и версии в вашей тетрадке после суток не исчезают. После долгого отключения можно получить оставшийся текущий текст, но пропущенную промежуточную правку восстановить не всегда возможно.

Очередь этих уведомлений одна для приложений одного пользователя. Когда одно приложение подтвердило записку, она исчезает и для остальных. Поэтому дополнительный режим включайте, если эту очередь не читает другая интеграция. Обычное сохранение сообщений от этого переключателя не зависит.

Собственные сообщения и «Мои заметки» собираются так же, как другие доступные чаты. Интервал — частота проверки изменений каталога, а не обещание закончить любую большую историю за минуту. Неизменившиеся чаты пропускаются до контрольной проверки, новые сообщения получают приоритет, ручная история имеет выделенные проходы. Состояния и ошибки всех работ видны в общем разделе «Очередь». При открытии страницы читается локальный каталог; плашка обновления показывает реально продолжающийся фоновый обход. Ручная кнопка «Обновить каталог» запускает дополнительный обход и не сохраняет старую историю сама по себе.

[Документация уведомлений Bitrix24](https://apidocs.bitrix24.ru/api-reference/chat-bots/chat-bots-v2/im.v2/events/event-get.html).

## Как проверить, что чаты скачиваются в фоне

Окно — это экран, который показывает работу. Скачивание выполняет отдельный обработчик, запущенный вместе с приложением. Ему не нужно открывать страницу чата или «Очередь».

1. В «Архиве чатов» отметьте нужные чаты и нажмите «Сохранить выбранные». Это запрос всей доступной истории, а не только сообщений, которые помещаются на экране.
2. В «Очереди» найдите группу с названием чата. Внутри отдельно показаны история, новые сообщения, сведения об участниках и каждый файл. Для истории видны обработанные сообщения и страницы; для файла — название и прогресс. Чат задачи также показывает номер задачи. Работы одного совещания собраны под его названием.
3. Закройте окно крестиком. Пока значок Meeting Archive остаётся в трее и компьютер не спит, очередь продолжает работать. При автозапуске Windows обработчики запускаются ещё до первого открытия окна.
4. Снова откройте окно через трей. «Последнее сохранение» и счётчики позволяют проверить, продвинулась ли очередь. Открытие окна читает состояние; оно не запускает заново всю историю.

**«Выход» в трее завершает приложение.** Сон или выключение компьютера тоже приостанавливают работу. Уже начатая локальная запись при штатном выходе завершается до закрытия базы. После следующего запуска незавершённая история продолжается с сохранённой страницы; повторно полученное сообщение не создаёт дубль.

Автоматизация на паузе или выключенное автосохранение останавливают автоматические задания. Явно выбранная вручную история и ручные скачивания файлов продолжаются. Автоматические вложения отдельно ждут своего расписания и выбранных типов. В очереди показана причина ожидания или ошибки и время следующего повтора, если он запланирован.

Большая история требует многих запросов. «Раз в пять минут» задаёт частоту поиска новых сообщений, а не срок окончания всех загрузок. Новые сообщения имеют приоритет, но ручная история получает регулярные проходы. История загружается страницами с соблюдением общей очереди и ограничений API; количество заданий не равно количеству одновременно скачиваемых сообщений.

Панель фоновой работы показывает, запущен ли обработчик, когда будет следующая проверка каталога и когда последний раз сохранена страница сообщений или файл. **Это отдельные показатели:** обновлённый каталог ещё не означает, что вся старая переписка сохранена. Полноту определяют диапазон и состояние истории конкретного чата. Завершённые группы по умолчанию свёрнуты; пользовательское раскрытие или сворачивание сохраняется при обновлении экрана. Счётчики группы учитывают также задания, которые ещё не показаны; «Ещё задания чатов» подгружает их в просмотр.

## Удаление переписки и вложений

В «Архиве чатов» можно удалить материалы текущего чата или отмеченных бесед. Кнопка у сохранённого вложения удаляет этот файл и его локальные варианты. «Настройки → Хранилище» позволяет очистить материалы всего архива чатов текущего аккаунта.

Диалог использует тот же стиль и подтверждение, что и совещания. Отдельно выбираются переписка с редакциями и контекстом, все/конкретные вложения и заметки. Заметки по умолчанию сохраняются. Показаны сообщения, файлы и объём; состав повторно проверяется перед действием. Удаление относится к этому компьютеру: чаты остаются в каталоге, источник Bitrix24 не изменяется.

После удаления переписки автоматика сохраняет только сообщения, созданные после удаления. Старая переписка возвращается по явному «Сохранить выбранные». Удалённое вложение не скачивается автоматически заново; восстановить его можно вручную либо повторным запросом истории с включённым типом файла. Незавершённая операция записывается отдельно и восстанавливается при продолжении/перезапуске, чтобы удалённое не возвращалось из индекса. Работавшую загрузку файла нужно сначала завершить.

Общая книжка аккаунта и ранее выбранный внешний дневник не удаляются кнопкой чата; заметки самой беседы выбираются отдельно. Ранее скачанные пользователем копии экспортов также остаются у него.

## Совместная аналитика

Один skill meeting-archive-files читает совещания, обычную переписку и чаты задач. Можно попросить: «Сопоставь выбранное совещание с обсуждением после него, покажи действующие решения и что изменилось». Разбор строит одну хронологию, показывает источники и различает подтверждённые и предполагаемые связи. Результат и краткий контекст сохраняются в ранее выбранную общую записную книжку; технические справки по форматам не создают отдельные независимые навыки.

В очереди чатов доступна массовая кнопка «Отменить старую историю». Она отменяет задания полной истории, выбранных периодов и ожидающих вложений сразу; новые сообщения, очередь совещаний и уже скачанные материалы не затрагиваются.

В очереди чатов можно отметить отдельные задания чекбоксами или выбрать все задания во всех страницах. Кнопка «Отменить» отменяет выбранные задания; совещания находятся в отдельном блоке.

В 0.2.40 исправлено состояние массовой отмены очереди: после «Выбрать все задания» кнопка «Отменить» становится активной и сохраняется активной после фонового обновления.
